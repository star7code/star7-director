## 两个节点

- **导演台工作站 — Star7**：分镜、镜头设置、生成队列、预览、二采、修脸和视频导出。
- **项目素材库 — Star7**：人物、场景、物品、音色、视频与文字素材管理。

本插件只注册这两个公开节点。H3 条件、采样调度、高清二采、人脸修复、预览和解码实现包含在包内；内部步骤不展开为额外画布节点。视频编码和导出由内置实现完成，无需 VHS / VideoHelperSuite。

工作站接收模型、文本编码器、视频 VAE、音频 VAE和素材库输入。模型权重由使用者准备；Python 库依赖明确列在 `requirements.txt` 中。

## 安装与示例

1. 将仓库或发行 ZIP 中的 `star7-director` 文件夹放入 `ComfyUI/custom_nodes/`。
2. 使用运行 ComfyUI 的同一个 Python 环境安装 `requirements.txt`，然后重启 ComfyUI。
3. 打开 [作者示例工作流](workflows/Star7导演台.json)，选择本机已有的模型、CLIP、视频 VAE、音频 VAE和所需 LoRA。
4. 在素材库添加素材，在导演台导入或添加镜头，检查参数后生成。

**示例的模型输入链**包含 [MiniMax H3 Chunk—Star7](https://github.com/star7code/minimax-h3-chunk-star7) 的模型加载、Sigma Shift、VEDA和显存分块节点，运行这份示例需要安装该插件。导演台包内的采样、二采、修脸和导出实现不调用这个外部插件；模型输入链可换成其他兼容的 ComfyUI 节点。示例中不包含模型或私人素材，加载后需选择本机模型并添加分镜。

ComfyUI 核心需要支持 MiniMax H3，旧版核心不能通过安装导演台补齐模型支持。不要用旧开发快照中的辅助节点工作流替代本次作者示例。

## 素材和分镜

素材使用稳定 ID，镜头描述通过 `@` 引用。普通素材改名不会替换提示词里的普通文字。素材缺失时保留素材卡、引用和镜头参数，补回文件后继续使用。

支持分镜导入、检查、导出、插入、右键增加镜头和拖动排序。导出素材大纲包含提示词编写 Skills 与当前素材目录。导入字母映射：

| 字母 | 模式 |
| --- | --- |
| I | 独立镜头 |
| R | 运动引导，接续前段动作与运镜 |
| F | 前段尾帧画面参考 |
| S / E / SE | 首帧 / 尾帧 / 首尾帧 |

新故事首段使用 I；后续镜头省略模式时默认 R。“运动引导＋重绘”仍可手动选择，但不是 R 的默认模式。素材大纲中的 Skills 与该映射一致。

## 生成、队列和状态

支持仅重新生成当前、仅二采／修脸、批量选择、继续生成全部。生成期间可追加任务，队列面板列出镜头顺序和一采、二采、修脸阶段；尚未开始的任务可取消；正在生成的任务可停止，使用指定任务编号，不发送全局中断。缺少依赖的镜头会报告原因，后续满足条件的独立镜头可继续。

浏览器刷新后恢复后台任务状态；即时预览不保留旧帧，后续预览或阶段结果会更新。关闭 ComfyUI 服务会中断正在执行的任务，已保存成品保留。

修改提示只比较明确的镜头输入：提示词、种子、秒数、输入/参考模式、首尾帧、实际引用素材、二采/修脸需求等。改回原参数会消除提示；外部模型或 LoRA 改动不会把全部镜头标为参数修改，执行缓存仍会核对真实生成条件。

普通连续性参考的前段一采变化单独提示，不自动连锁重跑。智能首尾帧使用上段尾帧时，实际输入变化纳入更新。已有二采/修脸成品不会仅因取消开关而自动降级。细节生成预设为 8 步。

## 导出与缓存

导出设置支持帧率、H.264 MP4 / H.265 MP4 / VP9 WebM、CRF或目标码率、像素格式、音频开关与码率、可选参数元数据。默认保持当前源视频参数并直接复制；调整设置只重新编码导出副本，不重新生成镜头、不覆盖原视频。帧率转换保持时长，通过补帧/减帧实现，不进行 AI 插帧。

生成成品保存到 `output/Star7-Director/年月日/`。导出当前镜头直接保存到指定目录，不额外保留一份永久导出副本；分段和合并导出各自新建“项目名称-分段导出/合并导出-时间戳”文件夹。分段按镜头顺序保存已有成品，尚未生成或文件不可用的镜头会列出并跳过。

缓存管理可勾选项目删除二采/修脸辅助缓存，保留素材与成品视频。当前项目以及正在生成／排队的项目禁止清理；请切换到其他项目，再清理空闲项目。支持按缓存类型选择，清理后单独二采／修脸或运动衔接可能需要重建对应缓存。

## 数据边界与更新

运行数据位于 `data/projects/<项目ID>/`，按项目保存配置、素材、队列记录和辅助缓存。更新代码时保留已有 `data/`，不要删除用户项目。

仓库和发行包不包含本地项目、私人素材、模型权重、缓存、日志或生成视频。普通工作流携带配置与素材引用；项目 ZIP 可携带素材，不打包模型、成品或 latent 缓存。更多说明：[文件管理](docs/STORAGE.md)、[架构与状态规则](docs/DESIGN.md)。
