# 本地文件管理

节点根目录中的 `.py`、`pipeline.json`、`web`、`vendor`、`schemas` 是程序，不应手工清理。正式示范工作流为作者提供的 `workflows/Star7导演台.json`。`docs` 是说明，`tests` 是开发回归脚本；测试生成的截图、日志和视频可以清理，历史 GPU 测试结果文件不是运行必需品。

日常项目采用“一项目一文件夹”：`data/projects/<项目ID>/`。文件夹名称使用稳定 ID，项目显示名称在界面中修改，避免重命名目录破坏已有索引。

| 项目文件夹内 | 用途 |
| --- | --- |
| `project.json` | 已保存的项目、分镜、种子、设置与工作流 |
| `state.json` | 生成运行状态与兼容读写快照 |
| `index.sqlite3` | 仅此项目的视频版本、缓存版本和成片索引 |
| `media/` | 本项目素材和缩略图归档 |
| `cache/` | 本项目一采、二采、修脸与运动衔接缓存 |
| `batches/` | 本项目后台任务和恢复进度记录 |
| `previews/` | 本项目可复用的临时连续预览；新版成功后清理旧版 |

`data` 根目录的共享服务目录不存独立项目：`media` 是上传／旧引用兼容区，`packages` 是打包临时区，`logs` 是运行和维护日志，`project-trash` 是项目回收区。这些不能混作某个项目的成品目录。项目创建后素材归入其自己的 `media`。

旧的根目录索引、项目 JSON、任务和预览记录会迁移到各自项目目录，索引迁移前留一份数据库备份在 `logs`，不会重新创建根目录项目索引。删除项目移走完整项目文件夹，正式视频保留。

正式生成与导出视频在 ComfyUI 的 `output/Star7-Director/年月日`，不在辅助缓存中：

- `S7D-时间戳-shot_xxx`：生成版本，更新版本带 `-2`、`-3` 等。
- `项目名称-分段导出-时间戳/`：按镜头顺序复制最近生成的视频，每次导出一个新文件夹；尚未生成或文件不可用的镜头会列出并跳过。
- `项目名称-合并导出-时间戳/`：合并导出的成片，每次导出一个新文件夹。

默认分段导出复制原有视频，不重新生成或转码，不移动、覆盖原视频或缓存。导出当前镜头直接保存到指定目录，不在日期目录额外保留永久导出副本。文件夹名称中的路径符号会替换为下划线。

“导出设置”保存在项目的 `export_settings` 中。默认设置直接复制原视频；修改帧率、格式或编码质量时，仅重新编码导出副本，不触发生成、不改变原视频。帧率转换通过补帧／减帧保持时长，不进行 AI 插帧。支持 H.264 MP4、H.265 MP4、VP9 WebM、CRF 或目标码率、像素格式和音频设置；编码实现内置，不需要视频节点插件。

辅助缓存列表可按一采、二采、修脸、运动衔接类型勾选一个或多个空闲项目，点击“清理所选项目”。当前打开的项目及生成／排队中的项目受后端保护；切换到其他项目后才能清理此项目。批量清理会跳过正在使用的项目，手工选择混入受保护项目则整次拒绝。删除只影响所选项目对应类型的 latent 检查点，项目、素材和已生成视频保留；之后单独二采／修脸或继续镜头可能需要重建对应缓存。正在导入的素材包及归档不能删除。

本地另存为保留视频路径索引并复制素材和辅助缓存，不复制视频；导出的项目 ZIP 包含素材和分镜设置，不包含成品和辅助缓存。

源码发布和 Git 更新不包含此数据目录。更新时保留已有项目、素材和成品。

## 领取导出结果

分段导出结果列出全部视频，可切换每段预览。列表高度跟随预览区，避免撑高弹窗。合并导出显示完整成片。“打开导出文件夹”在 Windows 本机打开输出目录；预览区已有播放器，不另提供打开视频按钮。

“下载到指定目录”先显示目录选择器，再将全部分段或合并视频保存到所选位置的同名文件夹；重复下载加编号，不覆盖已有内容。“下载 ZIP 包到指定目录”同样先选择目录，ZIP 保留整个导出批次的目录结构。

“导出当前镜头”直接选择目录并下载现有成品，不在 ComfyUI 的导出目录再建立永久副本。修改过编码设置时使用临时文件转码，传输完成后清理；默认直接读取原文件。官方 Windows 桌面版使用 Windows 原生目录选择窗口；支持 File System Access API 的 Chrome／Edge 使用浏览器目录选择器。保存位置由用户亲自选择，取消时不写文件。原生保存接口仅接受本机同源请求，不接受客户端指定的磁盘路径。
